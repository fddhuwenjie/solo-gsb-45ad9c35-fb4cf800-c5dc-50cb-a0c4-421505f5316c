# 古地图坐标校正与路线叠合校审台

一个用于古地图数字化校审的 Web 工具:在扫描图上录入控制点(像素坐标 ↔ 现代坐标),
系统通过**最小二乘仿射校正**把手工描绘的河流、道路等折线叠合到现代坐标网格上,
并自动进行**残差诊断**——标记离群控制点、显示每个控制点的局部偏差向量。
支持拖动控制点实时重算,并可保存 / 恢复校正版本。

此外提供**图幅接边校审**:选择两张已完成仿射校正的相邻图幅与接边容差,
系统把两侧同类折线的首/尾端点变换到现代坐标,自动筛选候选并以
**「匹配数最多、总距离最小」的全局最优一对一配对**给出接边建议(非逐端点贪心),
校审员可在同尺度叠加视图中逐条接受 / 驳回,决定按地图对与端点身份持久化,
重算后失效的旧决定自动标记为**待复核**。

技术栈:Python Flask + SQLite + 原生 HTML / CSS / JavaScript / SVG(无任何前端框架与外部依赖)。

## 快速启动

### Docker(推荐,一条命令)

```bash
docker compose up --build
```

启动后访问:**http://localhost:8000**

数据(SQLite 数据库 + 上传的扫描图)持久化在 `./data/` 目录。

### 本地运行(无需 Docker)

```bash
pip install -r requirements.txt
python app.py
```

访问 **http://localhost:8000**(可用环境变量 `PORT` 修改端口)。

## 使用流程

1. **上传扫描图**:顶部输入图名、选择图片文件,点击「上传扫描图」;
   也可以直接点「载入演示数据」生成一幅带控制点和河流/道路的演示图幅。
2. **录入控制点**:切到「📍 添加控制点」模式,在扫描图上点击已知地物
   (如钟楼、城门、渡口),在弹窗中填入其现代坐标(投影坐标或经纬度均可,全图需统一)。
   至少 3 个控制点才能解算仿射变换,建议 6 个以上并均匀分布。
3. **查看诊断**:右侧面板实时显示仿射参数、RMS 残差、每个控制点的残差与 ΔX/ΔY;
   残差超过 **2×RMS** 的点自动标红为「离群」,可取消勾选(不参与解算)或删除。
4. **描绘地物**:用「描绘河流 / 道路 / 其他」模式在扫描图上逐点描绘,
   双击或按「完成折线」结束;折线会按当前仿射参数自动叠合到右侧坐标网格。
5. **检查叠合**:右侧网格视图中,实心点为控制点现代坐标,空心圈为拟合位置,
   红色箭头为局部偏差向量(自动放大显示,放大倍数标注在标题栏)。
6. **精调与版本**:在「拖动/查看」模式下直接拖动扫描图上的控制点,松开后自动重算;
   满意后点「💾 保存版本」留档,可随时从版本列表「恢复」到任一历史状态。

## 图幅接边校审

顶部切换到「② 图幅接边校审」页签:

1. **准备两张图**:两张地图都需已完成仿射校正(各自至少 3 个启用的控制点),
   并已描绘河流 / 道路 / 其他折线。可点「载入接边演示图幅(两张)」一键生成
   东西相邻的西幅 / 东幅(东幅河口分岔,默认容差 200 时可看到冲突端点;
   另有一条灌渠两端无候选,作为未匹配示例)。
2. **选图与容差**:在「西幅/A」「东幅/B」下拉中选两张不同的地图,
   填入接边容差(单位与现代坐标一致,演示数据用 `200`),点「🔗 计算接边候选」。
3. **查看叠加视图**:两张图的折线按**同一尺度**叠加(A 幅实线、B 幅虚线),
   端点按状态区分:

   - 🟢 **已配对**(实心绿点):属于全局最优一对一配对的端点;
   - 🟠 **冲突端点**(橙色点):存在多个距离 / 夹角合格的候选,但受一对一约束未能落配;
   - ⚪ **未匹配**(空心灰点):在容差内没有任何合格候选。

   连线含义:绿色实线=建议配对,橙色虚线=落选冲突候选,
   青色粗线=已接受,红色点线=已驳回,黄色双线=待复核。
4. **校审**:在右侧列表(或直接点图中连线)选中候选,查看距离与反向夹角后
   点「接受」或「驳回」。接受强制一对一:若与已接受的配对共享任一端点会返回冲突,
   需先驳回原决定;任何决定都可「撤销」回到未决。
5. **重算与待复核**:修改控制点 / 折线或更换容差后重新计算——

   - **接受**的决定:候选仍成立且仍属于当前全局最优配对时保留为「有效」,
     否则标记为「⚠ 待复核」(几何已不成立的旧决定单列,可撤销);
   - **驳回**的决定:只要候选几何仍成立即保留;候选消失则转为待复核。

## 主要 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/maps` | 地图列表 / 上传新地图(multipart) |
| GET | `/api/maps/<id>/state` | 完整状态:控制点、折线、仿射参数、残差诊断、版本列表 |
| POST/PUT/DELETE | `/api/maps/<id>/control_points`, `/api/control_points/<id>` | 控制点增改删 |
| POST/DELETE | `/api/maps/<id>/polylines`, `/api/polylines/<id>` | 折线增删(删折线会把相关接边决定置为待复核) |
| POST | `/api/maps/<id>/versions` | 保存校正版本快照 |
| POST | `/api/versions/<id>/restore` | 恢复版本(覆盖当前控制点与折线) |
| POST | `/api/demo` | 生成单图演示数据 |
| GET | `/api/edge/maps` | 可接边地图列表(标注是否已校正、端点个数) |
| GET | `/api/edge/pairs/<id1>/<id2>?tolerance=` | 接边候选、全局最优一对一配对、持久化决定(重算状态) |
| POST | `/api/edge/pairs/<id1>/<id2>/decisions` | 接受/驳回候选 `{ep_a,ep_b,decision,tolerance}`,冲突返回 409 |
| DELETE | `/api/edge/decisions/<id>` | 撤销一条接边决定 |
| POST | `/api/demo_edge` | 生成两张可接边的演示图幅,返回 `{id_a,id_b,tolerance}` |

## 校正模型

对启用的控制点做最小二乘平差,解算六参数仿射变换:

```
X = a·x + b·y + c
Y = d·x + e·y + f
```

其中 `(x, y)` 为扫描图像素坐标,`(X, Y)` 为现代坐标。每个控制点的残差向量为
`(X_实测 − X_拟合, Y_实测 − Y_拟合)`,其模长超过 2×RMS 时判定为离群。
折线顶点逐点套用同一变换完成叠合。

## 接边模型

对两张图中每条折线取**首点(head)与尾点(tail)**,经各自仿射变换转到现代坐标。
端点身份为稳定字符串 `"<map_id>:<polyline_id>:<head|tail>"`,
只要地图与折线不被删除,重算后身份不变。

**候选筛选**(仅在同类折线端点之间):

1. 两端点现代坐标平面距离 ≤ 容差 `tolerance`;
2. 两端点各自指向相邻顶点的单位向量,把 B 侧向量取反后夹角 ≤ **45°**
   (共线相向为 0°,垂直为 90°),即两侧折线在接缝处应平顺对接而非折角或同向。

**全局最优一对一配对**:按河流 / 道路 / 其他分别建立二分图,
以匈牙利算法(Kuhn–Munkres)求最小权完美匹配。代价编码为
`可行边 = distance/tolerance ∈ [0,1]`,`不可行/哑边 = 1`:
任何多配一条真实边的方案严格更优,故**先最大化匹配对数,再最小化总距离**,
并通过补哑行/哑列允许端点留空。该解为全局最优,不采用逐端点按距离贪心
(贪心会被局部最短边锁住,少配对)。

**决定持久化与失效复核**:校审员的接受 / 驳回存入 `edge_decisions`
(唯一键为规范化地图对 + 两端点身份)。每次重算自动重新判定:

- accepted:仍在候选集且仍入选当前最优配对 → 保留有效,否则置 `review`;
- rejected:候选几何仍成立即保留;候选消失(超容差 / 夹角超限 / 折线删除)→ `review`。

待复核项在界面黄色高亮,可重新接受 / 驳回或撤销。
